# Product definition for the README

## Reader problem

A researcher sees several AI-generated accounts of a study and needs to trace each claim to a source. A category label or smooth paragraph is not enough if the source, model role, or current implementation limit is hidden.

## Readers and jobs

| Reader | Job |
| --- | --- |
| Researcher | Understand what the current fragment workflow can produce and where it does not yet provide paper-level synthesis. |
| Maintainer | Find implementation, tests, provenance fields, and open gaps. |
| Fresh agent | Rebuild the task context from repository files and GitHub issue state without treating old chat as authority. |

## Bounded promise

The README promises a readable path to one-fragment JEV classification and a structured draft record. It does not promise correct science, multi-source synthesis quality, or validated bias detection.

## Acceptance intent

A reader who has not seen the issue should be able to explain the current unit of work, source/decision role boundary, current evidence status, and next action. This is a review task, not a measured result unless an independent reader run is recorded.
