# README human review checklist

This checklist is an acceptance aid for issue #35. Automated validators cannot answer these questions.

## First-time reader

- [ ] Can a reader explain the human situation and the prototype's current promise after a short skim?
- [ ] Can a reader tell that one fragment, not a whole paper, is classified at a time?
- [ ] Can a reader distinguish untrusted source text from a JEV semantic judgment?
- [ ] Can a reader explain what the synthetic example does and does not demonstrate?
- [ ] Can a reader find an offline next step and a separate live JEV smoke?

## Evidence and boundaries

- [ ] Each implementation claim links to an immutable repository revision.
- [ ] Each source statement says what it supports and what it leaves open.
- [ ] Planned goals are not described as completed measurements.
- [ ] The assembler is described as a structural draft, not paper-quality synthesis.
- [ ] The bias pack is described as a signal rather than proof.

## Visuals and accessibility

- [ ] The hero image is useful after cropping at a narrow width.
- [ ] The supporting image does not imply automatic integration.
- [ ] Alt text describes the visible scene and relationship.
- [ ] Exact visible copy and hashes match the asset manifest.
- [ ] Prompt notes clearly say they are reconstructed, not verbatim original prompts.

## Status

The checklist is provided for an independent reviewer. Do not mark it complete without recording the reviewer and review result.
